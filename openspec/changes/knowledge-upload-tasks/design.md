## Context

后端以租户、知识库、文件类型和 MD5 检查重复，排除 failed 记录。前端现有进度事件没有生产方，确认弹窗只负责收集配置。

## Goals / Non-Goals

Goals: 在发送 PDF 正文前拒绝重复；批次结果可审阅；停止和撤销含义明确；切换页面保持队列。
Non-Goals: 分片传输、关闭浏览器后继续读取本地文件、自动重传状态不明的请求、生产部署。

## Decisions

- 使用可独立测试的队列执行器，加 Pinia 响应状态和 App 全局任务面板。最多三个并发，摘要/向量化仍由既有后台处理。
- 浏览器分块计算 MD5，定期让出主线程；每 200 个指纹预检一次。候选标识回传对应文档，服务端只返回必要字段。
- 预检沿用上传访问权限及有效租户。数据库按 hash 集合查询，避免下载全库文档或逐文件查询。
- 预检失败阻止该批正文上传；取消中断传输并停止派发。请求已可能被接收时标记结果待核实，重试先预检。
- 上传成功存储文档 ID，轮询解析状态。撤销只删除明确由该批创建的 ID；duplicate 响应中的已有 ID 不纳入删除。
- 用户/空间切换停止旧队列并禁止旧任务重试或撤销，避免动态认证头把请求发送到其他空间。
- 重复按内容及类型判断，不按名字猜测。同名不同内容可以上传；改名的相同 PDF 仍拒绝。

## Risks / Trade-offs

- 预检不是写入锁；正式上传保留服务器内容校验。多实例同时上传同一内容的数据库原子唯一约束不在本次范围，不宣称跨实例 exactly-once。
- 浏览器取消不能回滚已被服务端接收的请求。界面明确显示待核实，撤销只对已知新建 ID 生效。
- 不保存本地 PDF 到浏览器持久化存储；刷新前提示，重新选择文件后预检已上传部分。
